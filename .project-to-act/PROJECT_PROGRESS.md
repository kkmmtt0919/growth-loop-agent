|---|---|---|---|
| 首批用户与首发场景未最终确认 | 无法精确设计话术和评测集 | 负责人确认或完成首轮访谈 | 开放 |

| “KILL”名称与实际服务商未对应 | 本轮已通过受管 `deepseek` profile 接通 OpenAI-compatible LLM；若必须使用 KILL，仍需确认其准确名称和 endpoint | 提供 KILL 的准确名称与受管 profile，或继续使用已验证的 deepseek profile | 开放 |
| Android 正式发布条件未齐 | 当前 APK 为 debug 签名，且默认连接模拟器地址；真机/生产需要可访问的 HTTPS 后端、正式 keystore、隐私与微信授权联调 | 配置 `CAPACITOR_SERVER_URL`、正式签名和发布资料后重新构建 release | 开放 |

## 下一步

1. 把本机 localStorage 回读迁移到真正的用户/设备持久化层，并加入幂等账本与多用户隔离。
2. 为 Agent 增加 provider 故障、超时、长文本、键盘和屏幕阅读器回归，并建立可重复的语义评测集。
3. 若必须使用 KILL provider，确认准确名称后通过受管配置切换；当前默认已验证的 profile 为 `deepseek`。
4. 把四页原型迁移到持久化数据层，并加入幂等账本。
5. 接入微信登录/订阅授权适配层，使用测试账号验证回调与权限。
6. 配置微信公众号 AppID/Token 与公网 HTTPS 回调地址，完成真实后台校验后再开启生产消息。
7. 选择种子画像，开展 7 天 concierge 测试并回放 XP/积分规则。
8. 用真实学习样本校准题目难度、评分解释和晚报提问顺序，补充低分后的复习任务。
9. 用更多 Agent 学习样本回放路线阶段、验收标准和工具异常题，校准引导是否能持续推进真实开发。
10. 将运动/生活/休息分类、番茄钟状态和恢复节奏迁移到持久化数据层，并用真实用户样本校准提醒频率；当前仅提供通用行为建议，不替代医疗意见。
11. 为对话优先首页接入真正的后台定时任务：在用户授权和免打扰设置下触发每日 21:30 回顾，并把回顾结论写入服务端账本。
12. 配置 Android 的正式 HTTPS 后端与签名 keystore，补真机安装、断网/恢复和微信授权回归，再产出 release APK/AAB。
